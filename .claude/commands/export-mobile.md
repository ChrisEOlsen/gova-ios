# /export:mobile

Reads the linked gova-monolith web app and generates a structured context block
for the SEED.md Generated Context section. Run this from the gova-ios directory.

---

## Step 1 — Read Web App Path from SEED.md

Open `SEED.md` in the current directory. Find the `## Web App Path` value.

If the field is blank or still contains the placeholder text, STOP and tell the
developer:
> "Set `Web App Path` in SEED.md to the absolute path of your gova-monolith
> repo (e.g. `/Users/yourname/Desktop/repos/gova-monolith`), then run
> /export:mobile again."

Set `$WEB_APP` to the resolved absolute path for all subsequent steps.

---

## Step 2 — Read Go model structs

Read every `.go` file under `$WEB_APP/src/app/models/` (skip `.gitkeep`).

For each model file, extract:
- Struct name and all exported field names + types
- Any method signatures that appear on the struct (e.g. `GetAll`, `FindByID`,
  `Create`, `Delete`)

---

## Step 3 — Read JS modules (screens)

Read every `.js` file under `$WEB_APP/src/app/static/js/` **excluding** the
`lib/` subdirectory.

For each module, extract:
- Filename (becomes the screen name)
- Whether `requireAuth()` is called at the top (protected screen)
- All `get(...)`, `post(...)`, `del(...)` calls — record the path string
- Any form submission targets (look for the `api_endpoint` values in form
  initialisation, or `post(...)` calls inside submit handlers)

---

## Step 4 — Read registered routes from main.go

Read `$WEB_APP/src/app/main.go`.

Extract all `r.Get(...)`, `r.Post(...)`, `r.Put(...)`, `r.Delete(...)` route
registrations. Flag whether `/api/auth/login_token` is present — this means
`scaffold_mobile_auth` has already been run and Bearer token auth is ready.

---

## Step 5 — Call inspect_app (MCP supplement)

Using the `gova-builder` MCP tool, call `inspect_app` to get the canonical list
of models, handlers, pages, and routes as the server sees them. Use this to
cross-check Step 2–4 and catch any files that differ from the host filesystem
view (e.g. files generated inside the container but not yet on disk).

If the MCP is not connected or the call fails, continue with the file-read data
from Steps 2–4 and note the gap in the output.

---

## Step 6 — Generate and save mobile-seed-context.md

Write a file named `mobile-seed-context.md` in the current directory (the
gova-ios repo root). The file must contain exactly this structure:

```
### Web App Context
Generated by /export:mobile — paste into SEED.md § Generated Context.

#### Auth
- Mobile auth ready: [yes / no — based on login_token route presence]
- Protected screens: [comma-separated list of JS modules that call requireAuth()]

#### Models
For each model:
  **ModelName**
  Fields: field1 (Type), field2 (Type), ...
  Methods: GetAll, FindByID, Create, Delete [list what exists]

#### Screens → API Mapping
For each JS module (screen):
  **screen_name** [Protected] / [Public]
  - GET [path] → [what it loads]
  - POST [path] → [what it creates/updates]
  - DELETE [path] → [what it deletes]

#### All Registered Routes
[Paste the full route list extracted from main.go / inspect_app]
```

Do not invent any API paths, field names, or method names. Only include what was
read from the actual files.

---

## Step 7 — Report to developer

Tell the developer:

> "Context exported to `mobile-seed-context.md`.
> Open that file, copy its contents, and paste it into the `## Generated Context`
> section of `SEED.md` below the `<!-- PASTE ... -->` marker.
> Then run `/build` to translate the web app to iOS."

If `login_token` was NOT found in the routes, add:

> "Mobile auth is not set up yet. Before running /build, open your
> gova-monolith project in Claude Code and run `scaffold_mobile_auth` to add
> Bearer token endpoints to the API."
