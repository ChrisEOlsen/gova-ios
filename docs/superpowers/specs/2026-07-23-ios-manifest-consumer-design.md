# iOS Manifest Consumer — Design

**Date:** 2026-07-23
**Status:** Approved
**Scope:** Build 3a of 3 (the "3" build split into 3a/3b/3c) in the "API-first for native clients" effort. Entirely in the `gova-ios` repo.

---

## Problem

This is the payoff of the whole arc. Build 1 made the monolith's wire format
strict; Build 2 published a machine-readable manifest at `GET /api/v1/_manifest`
(and as committed source at `src/app/api.json`) describing every model — with
field types and nullability — and every endpoint. But `gova-ios` still does not
consume it. Its `/export:mobile` command reverse-engineers the API exactly as
before:

- **Step 2** reads every Go struct under `$WEB_APP/src/app/models/` to infer field names and types.
- **Step 3** parses every JS module for `get()`/`post()`/`del()` call sites and `requireAuth()`.
- **Step 4** greps `$WEB_APP/src/app/main.go` for `r.Get(...)` route registrations.
- **Step 5** calls the `inspect_app` MCP tool to cross-check.

Every one of those is inference over source that now has an authoritative,
machine-readable replacement. The nullability that Build 1 discovered and Build 2
published still dies here — the export re-derives it (or guesses) instead of
reading it. And the monolith's route reorganization (routes now come from
`routes_gen.go`, not hand-wired in `main.go`) means Step 4's `main.go` grep is
already partially blind.

Separately, the `_version` endpoint Build 1 added — the signal that protects a
stale App Store build — has no consumer. A shipped iOS app never checks it, so an
incompatible client fails opaquely instead of prompting the user to update.

This build makes `gova-ios` **read the contract instead of inferring it**:
`/export:mobile` transforms `api.json` directly, and the iOS app asserts its
version against `_version` at launch. Nullability, timestamp format, and auth
requirements arrive as stated facts.

---

## Decisions

| Area | Decision |
|---|---|
| Manifest source | Read `$WEB_APP/src/app/api.json` from disk — committed, deterministic, no running server, no MCP |
| Version gate | Included in 3a — a pre-committed Swift `VersionGate` checking `_version` at launch |
| Client version | `CFBundleShortVersionString` (added to `project.yml`), not a duplicated Config.plist key |
| Version-check failure | Fail **open** — never block the app because the check errored or the endpoint was unreachable |

3a is entirely in the `gova-ios` repo. It touches no monolith code.

## §1 Rewrite `/export:mobile` — transform the manifest, infer nothing

`.claude/commands/export-mobile.md` is rewritten. The new flow:

1. **Read Web App Path** from `SEED.md` (unchanged — Step 1 stays).
2. **Read `$WEB_APP/src/app/api.json`.** If the file is missing, STOP and tell the
   developer to build the web app first (scaffold at least one resource so the
   manifest is populated) — an empty manifest (`models:[]`, `endpoints:[]`) is
   valid but means there is nothing to translate yet.
3. **Transform** the manifest into the Generated Context block (format below).
4. **Write** it into `SEED.md` with the existing idempotent rule — everything
   from the top through the `<!-- /export:mobile WRITES BELOW THIS LINE -->`
   marker stays byte-for-byte unchanged; everything below is replaced.
5. **Verify** the write (developer section intact, block present exactly once,
   real models not placeholders).
6. **Report** to the developer.

Steps 2–5 of the *old* command (parse Go structs / JS / main.go / inspect_app)
are **deleted**. Export no longer reads any `.go` or `.js` file, no longer greps
`main.go`, and no longer needs the `gova-builder` MCP connection at all. It reads
one JSON file.

### The new Generated Context block

Written verbatim from the manifest — no invented paths, fields, or types:

```
### Web App Context
Generated by /export:mobile from api.json — manifest hash <manifest.hash>.

#### API
- api_version: <manifest.api_version>
- Bearer (mobile) auth ready: <yes if any endpoint has kind "mobile_login", else no>

#### Models
For each model, with the Swift type and optionality stated (never inferred):
  **<Pascal(model.name)>**  (table: <model.table>)
    - <field.name>: <field.type>[?] → <Swift type>[?]
    ...
  (id → Int; string → String; int → Int; boolean → Bool; float → Double;
   timestamp → Date [.iso8601]; a field with nullable:true becomes the optional form.)

#### Resources → endpoints
Endpoints that have a `model`, grouped by model then sorted by kind:
  **<model.name>**
    - <METHOD> <path>  [<kind>]  auth:<yes|no>
    ...

#### Auth endpoints
Endpoints with no `model` (kinds auth_login/auth_logout/auth_me/register/mobile_*):
    - <METHOD> <path>  [<kind>]

#### Screens to generate
  - One list screen per model that has a `list` endpoint: [<comma-separated model names>]
  - Login screen: <yes if bearer auth ready, else no>
```

### How the transform maps manifest fields

- **Swift type** is a fixed function of `field.type` (`string`→`String`,
  `int`→`Int`, `boolean`→`Bool`, `float`→`Double`, `timestamp`→`Date`). `id` is
  always `Int`.
- **Optionality** is `field.nullable` — a `nullable:true` field becomes the
  optional Swift type (`String?`). This is the fact that used to be guessed.
- **Bearer auth ready** is true iff some endpoint has `kind:"mobile_login"`.
- **A screen** is generated per model that has an endpoint with `kind:"list"`.
  (Until `scaffold_resource` (3b) lands, `list` is the only resource kind the
  manifest carries, so this is one list screen per scaffolded model — matching
  what exists today. When detail/create/update/delete kinds appear, the same
  grouping surfaces them with no export change.)
- **Protected**: a screen is protected iff its resource's endpoints are
  `auth:true`. (Today `scaffold_list` registers `auth:false`, so resources are
  public unless a custom auth-required endpoint targets them.)

Because the manifest already sorts models and endpoints canonically (Build 2),
re-running `/export:mobile` on an unchanged manifest produces a byte-identical
Generated Context — the export is deterministic.

## §2 iOS launch-time version gate

A pre-committed infrastructure file, in the same spirit as `APIClient.swift` and
`AuthManager.swift` — never regenerated by `/build`.

### `ios/GovaApp/Lib/VersionGate.swift`

```swift
@MainActor
final class VersionGate: ObservableObject {
    enum State { case checking, ok, updateRequired }
    @Published private(set) var state: State = .checking

    func check() async { ... }
}
```

- On `check()`, `GET /api/v1/_version` (reusing `APIClient`), decode
  `{ api_version, min_client_version, manifest_hash }`.
- Read the app's own version from `Bundle.main.infoDictionary["CFBundleShortVersionString"]`.
- Compare with a pure `compareSemver(_ a: String, _ b: String) -> ComparisonResult`
  (split on `.`, numeric compare component-wise, missing components treated as 0).
- `clientVersion < min_client_version` → `state = .updateRequired`.
- Otherwise → `state = .ok`.
- **Any failure** (network error, decode error, endpoint unreachable, malformed
  version) → `state = .ok`. **Fail open.** A shipped app must never brick itself
  because the version endpoint hiccuped; the gate only blocks when it can prove
  the client is too old.

### `ios/GovaApp/Lib/UpdateRequiredView.swift`

A simple blocking full-screen SwiftUI view: an icon, "Update Required", a line of
copy ("A newer version of this app is required to continue."), and nothing that
dismisses it. No App Store deep-link is assumed (bundle-specific); the copy just
instructs the user to update.

### Wiring — `GovaAppApp.swift`

```swift
@main
struct GovaAppApp: App {
    @StateObject private var auth = AuthManager.shared
    @StateObject private var versionGate = VersionGate()

    var body: some Scene {
        WindowGroup {
            Group {
                if versionGate.state == .updateRequired {
                    UpdateRequiredView()
                } else {
                    ContentView().environmentObject(auth)
                }
            }
            .task { await versionGate.check() }
        }
    }
}
```

While `state == .checking` (the initial value) the app shows `ContentView` — the
check is non-blocking, so a slow network never delays launch; the gate only
switches to `UpdateRequiredView` if the check positively determines the client is
too old.

### `ios/project.yml`

Add `CFBundleShortVersionString: "1.0.0"` (and `CFBundleVersion: "1"`) to the
target's `info.properties` — the project currently sets no version, so
`CFBundleShortVersionString` is absent and the gate would otherwise read nil (and
correctly fail open). Setting it gives the app a real, comparable version.

### Testing note

There is no Swift test runner in this repo (consistent with the monolith's
"no JS test runner" constraint — the iOS toolchain here is `xcodebuild` only).
`VersionGate` and `compareSemver` are verified by `xcodebuild build` succeeding
and by reasoning about the comparison cases in the plan. `compareSemver` is
written as a pure free function so its logic is inspectable in isolation.

## §3 gova-ios CLAUDE.md + `/build` reorientation

The translation guide and build workflow currently think in terms of "one screen
per JS module." With the manifest, screens derive from resources.

### `CLAUDE.md`

- **Step 1 / Step 4 headers** ("The list of screens (one per JS module in the web
  app)", "Build screens (one per JS module in the web app)") → "one per model
  with a `list` endpoint in the Generated Context."
- **Web-to-iOS Pattern Mapping** table: the left column is titled "Web (JS module
  pattern)" — reframe as the manifest resource pattern (list endpoint →
  `List{ForEach}`, create endpoint → create form/sheet, delete endpoint →
  `.onDelete`). The SwiftUI equivalents are unchanged; only the source framing.
- **Step 3 (model typing):** already manifest-aware as of Build 2 (it states
  nullability comes from the manifest). Keep, and align the type table's key
  column to the manifest field types (`timestamp → Date`, already present).
- **Add a short "Version gate" note** to the Infrastructure Files section: it is
  pre-committed like `APIClient`/`AuthManager`, checks `_version` at launch, fails
  open, and must never be regenerated.
- **Infrastructure Files list:** add `VersionGate.swift` and `UpdateRequiredView.swift`.

### `.claude/commands/build.md`

- **Step 3 (Brainstorm)** and **Step 4 (plan order)** reference "one per JS module
  in Generated Context" → "one per model/resource in the Generated Context." The
  `scaffold_mobile_auth` note stays (auth scaffolding is monolith-side and
  unchanged until 3c).
- No change to the Swift-generation mechanics (ViewModel/View pairs, `xcodegen
  generate`, `xcodebuild` verification) — those are correct as-is.

## §4 Scope boundary

Out of scope, deferred:
- **`scaffold_resource` / full CRUD** (3b) — a monolith build. Export already
  handles whatever endpoint kinds the manifest carries; when 3b adds
  detail/update/delete, export surfaces them with no change.
- **Unified auth** (3c) — a monolith build. The export reads whatever auth
  endpoints the manifest lists, regardless of which tool produced them.
- **Any monolith change.** 3a is entirely in `gova-ios`.
- **`/prep` command** — it collects app name / path / URL and then calls
  `/export:mobile`. It needs no change; it delegates to the rewritten export.
- **An App Store deep-link** in `UpdateRequiredView` — bundle-specific; the copy
  instructs the user generically.
