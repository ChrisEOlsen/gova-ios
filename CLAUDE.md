# Agent Context: GOVA iOS

You are the iOS lead for a GOVA app. A companion `gova-monolith` project owns
the Go backend and the JSON API; you build only the native SwiftUI client
against it.

`SEED.md`'s **Generated Context** is your source of truth for screens, models
and endpoints. `/export:mobile` writes it by transforming the web app's
committed `src/app/api.json`. Never edit it by hand — re-run the export.

The Xcode project is generated by XcodeGen: **after adding any Swift file, run
`xcodegen generate` inside `ios/`**, or the file is not in the project and the
build silently ignores it.

## How to talk to me

Plain language. Short sentences. Answer first, then the reason if I need one.

- Lead with the answer or the thing that broke. No preamble, no recap of what I
  just asked.
- One idea per sentence. Cut every clause that does not change what I do next.
- Say it straight: "the decode fails on the date" beats "it appears the decoder
  may not be handling the date format as expected".
- Prefer a short list or a file path over a paragraph. Point at
  `ios/GovaApp/Models/Foo.swift:42` instead of describing where the code is.
- Skip the hedging and the flattery. If you are unsure, say "not sure" and say
  what would settle it.
- No status essays. Done is "done, builds clean". Broken is "broken: <one line>".
- Only explain at length when I ask why, or when a decision has a real tradeoff
  I have to make.

Reading your output is work. Make it cheap.

Run `./install-claude.sh` once per clone, or `./install-codex.sh` if you work

## The wire contract

Everything the API guarantees is in the monolith's **`docs/API-CONTRACT.md`** —
the response envelope, the error codes, the date format, pagination, and the
manifest fields this repo reads. Read it rather than re-deriving anything.

Consequences you will hit constantly:

- Every response is wrapped in `{"ok":…,"data":…,"meta":…,"error":…}`.
  `APIClient` unwraps it, so your `Codable` types describe the **`data`
  payload**, never the envelope.
- Timestamps are RFC3339 with no fractional seconds, which is exactly why
  `APIClient` uses `.iso8601` in **both** directions. A `timestamp` field is a
  `Date` — put the `Date` straight in the request body and let the encoder
  write it. Never format one by hand, and never reuse a `datetime-local`
  string for it: the server parses a `timestamp` with `time.RFC3339` and
  rejects `2026-07-27T11:45`.
- **`data` is omitted when there is no payload.** `jsonOK(w, nil)` — what every
  freshly scaffolded `gova handler` returns — emits `{"ok":true}` and nothing
  else. Decoding that as a type throws `.decode`, so call the **discarding**
  overload (`try await APIClient.shared.post(path:)`) for any endpoint whose
  response is `empty`, absent from the manifest, or not yet implemented.
- **Lists are one window, not the whole table.** The default is 50 rows. See
  Pagination below.
- A `401` means the bearer token is dead. `APIClient` logs out on it
  automatically, which returns the app to `LoginView`; a ViewModel does not
  need to handle it beyond showing its error.
- **The client holds no cookies, by construction.** `APIClient`'s session is
  ephemeral with cookies refused. This is load-bearing: the server's CSRF
  exemption is for *bearer* requests, and `login_token` is the one call with no
  bearer token yet, so its exemption rests entirely on a native client having no
  cookies to replay. Accept one — `URLSession.shared` would, from the launch
  `_version` call — and every login answers `403 invalid CSRF token`. Never
  swap in `URLSession.shared` or a session with a cookie jar.

Auth is always present — the monolith ships it. The bearer endpoints
(`login_token`, `logout_token`, `me_token`) always exist; there is nothing to
scaffold and no "is auth set up?" check to make. Two traps:

- `login_token` answers `{"token","user"}`. Decode it with **`LoginResponse`**
  from `Lib/AuthManager.swift`, not a type you declare yourself — the committed
  `api.json` abbreviates this schema to `{token}` and is wrong.
- `register` sets a browser **cookie** and returns no token. A native
  registration screen must follow a successful register with `login_token`
  using the same credentials, or offer no registration at all.

### Pagination

Every list endpoint takes `?limit=` (1–200, default **50**) and `?offset=`, and
answers with `meta: {limit, offset, total}`.

`get` discards `meta`, which is fine for a list that cannot grow — a short
lookup table. Any list that can exceed 50 rows uses `getPage` instead:

```swift
let page: Page<Item> = try await APIClient.shared.getPage(
    path: "/api/v1/items?limit=50&offset=\(items.count)")
items += page.items
canLoadMore = page.hasMore
```

and the list shows a "Load more" row while `canLoadMore`. A list screen that
silently stops at 50 rows is a defect, not a simplification.

### Query strings

Interpolating a value into a query is fine for the generated shapes, whose
values are all `Int` — `?filter=client_id:\(parentId)`, `?offset=\(items.count)`.
It breaks the moment a value is text: an email's `+`, a space, an `&` in a free
text search. Any query carrying a non-`Int` value is built with
`APIClient.path`:

```swift
let path = APIClient.path("/api/v1/notes", query: [
    .init(name: "filter", value: "author:\(email)"),
    .init(name: "limit", value: "50"),
])
```

### The launch sequence

`GovaAppApp` runs `VersionGate.check()` and `AuthManager.restoreSession()`
concurrently at launch, and `restoreSession` is what clears `auth.isRestoring`
— so it runs on every launch, whatever else changes.

`ContentView` gates in this order, and it is not interchangeable:

1. `auth.isRestoring` → a `ProgressView`. A Keychain token proves only that one
   was saved once.
2. `auth.isLoggedIn == false` → `LoginView`.
3. otherwise → the app.

Checking `isLoggedIn` first renders the app on an unvalidated token: a flash of
screens, a burst of 401s, then the login screen anyway.

## Translation guide

### Step 1 — Read the Generated Context

Confirm the screens listed, each model's fields and types, which endpoints each
screen uses, and whether auth is required. If the block is empty, STOP and tell
the developer to run `/prep`.

### Step 2 — Swift models

One struct per model in `ios/GovaApp/Models/`. `Codable`, `Identifiable`, `var
id: Int`, `CodingKeys` mapping snake_case to camelCase.

| Manifest type | Swift |
|---|---|
| string | `String` |
| int | `Int` |
| boolean | `Bool` |
| float | `Double` |
| timestamp | `Date` |

A nullable field is an optional — the manifest records nullability explicitly,
so you never need to read the SQL schema.

The struct above describes what the API **returns**. A create or update body is
a separate `Encodable` struct holding only the fields the endpoint's `request`
schema lists: `id` and `created_at` are set by the server, and so is the
`user_id` of an `owned` model, which never appears in `fields` at all.

```swift
struct Item: Codable, Identifiable {
    let id: Int
    let name: String
    let createdAt: Date

    enum CodingKeys: String, CodingKey {
        case id, name
        case createdAt = "created_at"
    }
}
```

### Step 3 — Screens, driven by endpoint kinds

Generate exactly the screens a resource's **kinds** support. **Never invent an
operation the manifest does not expose.**

| Kind | Generate |
|---|---|
| `list` | list screen; `vm.load()` → `GET /api/v1/{plural}` |
| `detail` | detail screen reached by tapping a row; `vm.loadDetail(id)` |
| `create` | create `Form` in a `.sheet` from a `+` toolbar button, then reload |
| `update` | edit `Form` on the detail → `PUT`, then reload |
| `delete` | `.onDelete` swipe on the list, and/or a delete button on the detail |

**Field format → control.** A field carrying `[format: X]` gets the matching
control and write format — never a plain `TextField`:

| format | control | value sent |
|---|---|---|
| `datetime-local` | `DatePicker([.date, .hourAndMinute])` | `2026-07-27T11:45` — no seconds, no `Z` |
| `date` | `DatePicker(.date)` | `2026-07-27` |
| `time` | `DatePicker(.hourAndMinute)` | `11:45` |
| `email` | `TextField` + `.keyboardType(.emailAddress)` + no autocapitalization | the string |
| `json` | monospaced `TextEditor` | the raw JSON string |

A `datetime-local` field is a `String`, not a `Date` — distinct from a
`timestamp`, which is a `Date` with seconds and a zone.

Two controls the manifest cannot ask for, because no `format` carries them:

- A field **named** `password` (the login and register bodies) is a
  `SecureField` with `.textContentType(.password)` — never a `TextField`.
- A `timestamp` field in a write body is a `DatePicker([.date, .hourAndMinute])`
  bound to a `Date`, and it goes into the body as a `Date`. `APIClient`'s
  encoder writes the RFC3339 the server parses; formatting it yourself is how
  you get a 400.

**Children nest.** The **Relationships** section lists each child and its
foreign key. A child gets **no top-level screen**: its list renders inside the
parent's detail, loaded as `?filter={fk}:{parentId}`, and its create sheet
pre-fills the fk. Only resources with no `references` field become tabs — the
`Top-level list screens` line says which.

**Custom endpoints become actions.** Each `kind:custom` entry carries a
`summary`, its schemas, and `attach` + `control` hints. `control: button` → a
button that calls the endpoint; `control: form` → a `.sheet` with one control
per request field (from the request's inline `fields`, or from the named model
when the schema is `object(model)`). `attach: detail` puts it on the detail
screen, `attach: list` on the list toolbar. Call through `APIClient.shared` per
the endpoint's method.

Read the action's **response** line before you write the call:

- `object(model)` or `object{…}` → decode it and apply the result.
- `empty`, or no response line at all → use the discarding overload and reload
  the screen afterwards. A newly scaffolded handler answers `{"ok":true}` until
  someone implements it, so this is the common case; decoding it throws.

**Per resource:**
- `ViewModels/NameViewModel.swift` — all fetch and mutation logic, `@Published`
  state (`items`, an optional `selected` if a `detail` kind exists, plus
  `isLoading` and `errorMessage`), one `async` method per available operation
- `Views/NameListView.swift`
- `Views/NameDetailView.swift` — only if a `detail` kind exists

Build the ViewModel first, then the View. Every ViewModel declares:

```swift
@Published var isLoading = false
@Published var errorMessage: String? = nil
```

and every View renders it when non-nil:

```swift
if let msg = viewModel.errorMessage {
    Text(msg).foregroundStyle(.red).font(.caption)
}
```

### Step 4 — Navigation

Wire `ContentView.swift` with `NavigationStack` destinations for each screen. If
auth is required, show `LoginView` when `auth.isLoggedIn == false`.

Give every `TabView` item, list row, and detail root a stable
`.accessibilityIdentifier` — the UI tests need them.

## Architecture rules (non-negotiable)

1. **MVVM.** No network calls in Views.
2. **`APIClient.shared` only.** Never raw `URLSession`.
3. **Keychain only.** Never a token in `UserDefaults` — `AuthManager` owns it.
4. **No force unwrap.** No `!` on optionals; use `guard let`.
5. **`@MainActor` on ViewModels.**
6. **async/await only.** No completion handlers.
7. **`NavigationStack`**, never the deprecated `NavigationView`.
8. **Every API call has a visible error state.**
9. **`Config.plist` for the base URL.** Never hardcode it.
10. **`xcodegen generate` after adding any file.**
11. **No hyphens in app copy.** Any text a user reads on screen — titles, labels,
    placeholders, button text, empty states, error messages — carries no `-`
    character. Rewrite rather than hyphenate: "sign in", not "sign-in". Em dash
    (—) for a sentence break, en dash (–) for a range. Prose only; identifiers,
    URLs, SF Symbol names and date formats are untouched.

## Pre-committed infrastructure

`ios/GovaApp/Lib/` is hand-written and shared. **Never regenerate these** —
import and use them.

- **`APIClient.swift`** — `shared`, reads `API_BASE_URL` from `Config.plist`,
  injects `Authorization: Bearer` when `AuthManager` holds a token, unwraps the
  envelope, encodes/decodes dates as RFC3339, and runs on a **cookieless**
  ephemeral session (see the wire contract above). `APIClient.path(_:query:)`
  builds an encoded query string. Throws `APIError`:
  `.configuration`, `.network`, `.decode`, `.server(statusCode:message:)`, and
  logs out on a `401` carrying a token.
  - `get` / `getPage` — the latter keeps `meta`, returning `Page<Item>`
    (`items`, `meta`, `hasMore`).
  - `post` / `put` / `delete` — each has a **decoding** and a **discarding**
    overload; `post` additionally has both without a request body. Swift picks
    by whether you bind the result, so `try await client.post(path: p)` on its
    own line discards and `let x: T = try await client.post(path: p)` decodes.
- **`AuthManager.swift`** — `shared`, `ObservableObject`, `isLoggedIn`,
  `currentUser`, `nonisolated var token` (in-memory, Keychain-backed),
  `login(token:user:)`, `logout()`, `isRestoring`, and `restoreSession()` —
  called once at launch from `GovaAppApp`, it validates a Keychain token
  against `me_token`, fills `currentUser`, and clears `isRestoring`. Defines `UserInfo`, `LoginResponse` and
  `LoginRequest`; a login screen uses those three rather than declaring its own.
- **`VersionGate.swift`** — checks `GET /api/v1/_version` at launch against this
  build's `CFBundleShortVersionString`. **Fails open**: only a provably-too-old
  client is blocked.
- **`UpdateRequiredView.swift`** — the blocking screen `VersionGate` shows.

## Verification

```bash
.claude/skills/gova-build-execution/scripts/verify
```

It runs `xcodegen generate`, builds, and runs both test targets against the
first available iPhone simulator — do not hand-write an `xcodebuild` line with a
specific device name, since the machine may not have that device. Override with
`GOVA_SIM="iPhone 17 Pro" scripts/verify` if you need a particular one.

`GovaAppTests` holds unit tests; `GovaAppUITests` holds `SmokeTest.swift`, an
app-agnostic test that launches, taps every tab, and confirms a row push.

**The smoke test is not sufficient on its own.** It detects a push only
opportunistically and skips a resource whose list turns out to be read-only. So
**for each resource with a `detail` endpoint, add a UI assertion that tapping
its row opens a detail showing its data** — assert on a known field label or the
detail root's `accessibilityIdentifier`, then pop. This is a requirement: it is
what actually proves that resource's detail binds, which no build, unit test, or
grep can see.

## Device deploy

- **LAN http works by default** — `project.yml` ships an ATS
  `NSAllowsLocalNetworking` exception, so a physical iPhone can reach

  `/launch` https tunnel.
- **Signing:** `/prep` writes `DEVELOPMENT_TEAM` into `project.yml` so it
  survives `xcodegen generate`. Blank is fine for the simulator.

## Harnesses

This project runs under **Claude Code** and **Codex**, with the same workflow,
because everything defining it lives in files both read:

| What | Where | How each finds it |
|---|---|---|
| These rules | `CLAUDE.md` | Claude Code directly; Codex via the `AGENTS.md` symlink |
| `/prep`, `/build`, `/export:mobile` | `.claude/commands/` | Claude Code reads the dir; `.agents/skills/gova-{prep,build,export-mobile}/SKILL.md` point Codex at it |
| The three `gova-*` skills | `.claude/skills/` | Claude Code reads the dir; `.agents/skills/*` symlink into it for Codex |

Install with `./install-claude.sh`, `./install-codex.sh`, or both.
**Nothing above is duplicated per harness. Do not fork it.**

The three `gova-{prep,build,export-mobile}` skills hold a pointer, not a copy:
Codex follows a symlinked skill *directory* but ignores a symlinked `SKILL.md`
*file*, and a command is one file, so there is nothing to link a directory to.
They say which file to read and stop.

Four differences:

1. **Batched questions** — `AskUserQuestion` (Claude Code). Codex has no
   equivalent, so ask a batch as one numbered list in a single message. Never
   one question per message in either.
2. **Subagent dispatch** — Claude Code takes `subagent_type: general-purpose`
   plus an explicit `model`. Codex takes `spawn_agent` with `agent_type`
   `worker` (implement, fix) or `explorer` (review), an explicit `model`, and
   `fork_turns` set to `"none"` or a turn count — a full-history fork inherits
   the parent's model and refuses the override. This repo pins no custom agents.
3. **Final review** — the `code-review` skill (Claude Code) or `/review`
   (Codex).
4. **Project trust** — Codex ignores `.codex/` entirely until the project is
   trusted. `install-codex.sh` writes that entry; without it the concurrency
   setting silently does not apply.

Codex loads its configuration at startup. Restart it after touching `.agents/`,
`.codex/` or `AGENTS.md`.
